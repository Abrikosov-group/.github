# Правила работы с pull request

Эти правила действуют для репозиториев организации `Abrikosov-group`, если в конкретном репозитории не опубликована более подробная локальная инструкция.

## Перед отправкой на ревью

1. Завершите разработку и собственную проверку изменений.
2. Убедитесь, что автоматические тесты и проверки CI прошли успешно.
3. Переведите pull request из состояния **Draft** в **Ready for review**.
4. Проверьте, что описание PR объясняет цель и основные изменения.

## Запуск ИИ-ревью

В репозиториях, где подключён общий workflow ревью, проверка двумя ревьюерами
запускается автоматически при открытии готового PR, при переводе PR в
**Ready for review**, при повторном открытии, после каждого нового коммита и
при фактической смене целевой base-ветки:

- GPT-5.3-Codex-Spark с усилием `xhigh`;
- Claude Sonnet 5 с усилием `xhigh`.

Для ручного повторного запуска добавьте в обсуждение PR отдельный комментарий:

```text
/review-all
```

Команда повторно запускает независимую проверку двумя ревьюерами.
После принятия команды на комментарии появляется 👀. Пока запуск ожидает общей
очереди, реакция не меняется. При фактическом начале ревью 👀 заменяется на 🚀,
а в PR создаётся статусный комментарий с отдельным состоянием
GPT-5.3-Codex-Spark и Claude. Если запуск не дошёл до начала ревью, бот по
возможности заменяет 👀 на 😕. После завершения статусный комментарий обновляется
итогом и ссылкой на журнал.

Codex Spark выполняется на защищённом серверном runner через подписочный вход
ChatGPT, без OpenAI API-ключа и без встроенного GitHub Security Review.
Результаты обоих ревьюеров относятся к зафиксированным Base и Head SHA.
Перед запуском каждой модели и публикацией результата workflow повторно
проверяет, что PR остаётся открытым, находится в Ready и сохраняет точные
Base/Head. Закрытый или возвращённый в Draft PR завершается без поздней
публикации результата.

## После запуска

1. Дождитесь завершения проверок во вкладке **Checks** или **Actions**.
2. Прочитайте итоговые комментарии ревьюеров в PR.
3. Автор изменений самостоятельно проверяет замечания и исправляет подтверждённые проблемы.
4. После каждого нового коммита дождитесь нового автоматического ревью актуальной версии кода.
5. Объединяйте PR с целевой веткой только после успешного CI и обработки существенных замечаний.

## Границы ответственности ИИ-ревьюеров

ИИ-ревьюеры:

- анализируют изменения и публикуют замечания;
- не изменяют код;
- не отправляют исправления;
- не объединяют и не закрывают PR.

Ответственность за проверку выводов ИИ, исправления и окончательное решение остаётся у автора PR и ответственного разработчика.

## Если команда не запустилась

Проверьте последовательно:

1. PR переведён в состояние **Ready for review**.
2. Для ручного повтора команда опубликована отдельным комментарием без дополнительного текста.
3. Во вкладке **Actions** появился запуск workflow ревью.
4. В репозитории установлен workflow `.github/workflows/review-all.yml`,
   вызывающий центральный workflow `Abrikosov-group/.github`.

Не публикуйте токены, ключи и значения GitHub Secrets в комментариях, коде или описании PR.
